# Контракт генерации VPN-профилей и QR

Зафиксирован 27.09.2026 по прямому указанию пользователя. Сохранять при всех
обновлениях, включая крупные обновления бота и установщика. Менять только для
конкретной подтверждённой ошибки совместимости или явно запрошенной функции.
Не переписывать и не унифицировать работающий генератор попутно с другой задачей.

## Источник и путь выдачи

- `vpn/amneziawg/awgctl.sh`: общий исходник AWG-контроллера. На сервере WG 3.1
  запускается как `/usr/local/sbin/awg3ctl` со своим `awg3ctl.env`.
- Клиентский `.conf` — источник параметров профиля. Генерация нового представления
  не должна менять ключи, PSK, адреса, параметры обфускации или серверных peers.
- `make_amnezia_vpn_payload_files` создаёт JSON, сжатый контейнер и строку `vpn://`.
- `app/actions.py`, `qr_items_for_server` и `send_qr_image_for_platform` выбирают
  представление для кнопки. Названия полей API исторические: нельзя по одному
  слову `android` определять, какому приложению предназначен QR.

## Кнопки и форматы

| Выдача | Содержимое | Назначение |
| --- | --- | --- |
| QR для iPhone | Текст клиентского `.conf` | AmneziaWG |
| QR для Android | Тот же текст клиентского `.conf` | AmneziaWG |
| QR AmneziaVPN | Одна строка base64url от qCompress-совместимого JSON, без `vpn://` и без `=` | Полное приложение Amnezia VPN |
| Строка `vpn://` | `vpn://` + та же base64url-строка | Полное приложение Amnezia VPN |
| Файл `.conf` | Исходный клиентский конфиг | Клиент с поддержкой соответствующей версии AWG |

Обычные кнопки iPhone/Android берут `ios_qr_png_base64`, с fallback на
`qr_png_base64`. Кнопка AmneziaVPN берёт `android_qr_png_base64`. Если его нет,
существующий код допускает единственный элемент `vpn_qr_png_base64_items`, но
отклоняет несколько частей. Это исторический fallback, не основание менять
основной одиночный формат. Base64 PNG в API — транспорт картинки, его нельзя
путать с base64url, закодированной внутри QR.

Есть отдельный исторический формат частей `amqrpng`: байты `07 C0`, число частей
(u8), индекс с нуля (u8), длина части (u32 big endian), содержимое части,
затем base64url. Он не равнозначен обычному QR `.conf` или одиночному QR
AmneziaVPN. Не заменять им штатную выдачу.

## Native JSON для Amnezia VPN

Внешний объект содержит `description`, `hostName`, `containers`,
`defaultContainer`, при наличии DNS — `dns1` и `dns2`.
Внутри элемента `containers`: `container` и объект `awg`.
`awg.last_config` — **строка JSON**, не вложенный объект. Объект содержит
`config` с полным исходным текстом `.conf`, `hostName`, числовой `port`,
`client_priv_key`, `client_ip`, `server_pub_key`, массив `allowed_ips`, `mtu`,
при наличии `psk_key`, `persistent_keep_alive` и параметры AWG.
Обёртка `awg` содержит `isThirdPartyConfig: true`, строковый `port`,
`transport_proto: "udp"` и определённую генератором версию протокола.

Текущие правила определения версии (сохранять старые ветки):

| Признак | protocol_version | container / defaultContainer |
| --- | --- | --- |
| Есть HeaderProtectionKey | `3.1` | `amnezia-awg2` |
| Иначе есть S3 и S4 | `2` | `amnezia-awg` |
| Иначе есть I1–I5 | `1.5` | `amnezia-awg` |
| Иначе | Поле не добавляется | `amnezia-awg` |

Сериализация: компактный JSON UTF-8 → длина несжатого UTF-8 в 4 байтах
big endian → zlib уровня 8. Затем base64url без padding `=` и переносов строк.
Для текстового ключа добавляется префикс `vpn://`; для одиночного QR — нет.
PNG создаётся `qrencode -t PNG -s 12 -m 4 -l L` для native QR.

## Обязательная проверка при изменениях

1. Зафиксировать конкретный дефект, ОС, приложение и версию. Не переносить
   требования Amnezia VPN автоматически на отдельное приложение AmneziaWG.
2. Сохранить исходный генератор и способ отката. Не перезаписывать рабочий
   сервер целиком локальным файлом с посторонними изменениями.
3. Запустить `tests/test_amnezia_payload.py`: roundtrip, сохранность `.conf`,
   параметры AWG 1/1.5/2/3.1. При изменении выбора кнопок проверить и bot logic.
4. Проверить реальную генерацию PNG и вместимость QR; создание PNG само по себе
   не доказывает успешное сканирование на телефоне. Отдельно проверить импорт
   в целевом приложении и подключение. Не выводить ключи в отчёты или логи.
5. Убедиться, что профили и peers сохранены, обновить SHA256SUMS для изменённых
   файлов. Проверить, что установщик использует исправленный контроллер.
6. Дополнить этот документ результатами и ограничениями. Старые архивы сборок
   не получают исправление автоматически; при выпуске пересобрать и проверить
   новый архив. Не публиковать в GitHub без соответствующего запроса.

## Переключение входящего и исходящего IP, 30.09.2026

По требованию пользователя выбранный адрес применяется также к VPN-выходу.
Это отдельная политика сети: форматы QR, vpn://, выбор приложения и параметры
кодирования не изменяются. В профиле меняется только Endpoint/CONNECT_HOST.
Ключи, PSK и обфускация сохраняются. Резервный IP остаётся на интерфейсе,
его VPN-порты закрыты. SSH и прочие службы не входят в эту блокировку.
Старые скачанные профили автоматически не обновляются.
Собственная таблица inet vpnbot_ip использует NAT priority 90, до прежних
iptables SNAT/MASQUERADE priority 100. Прежние правила сохранены для отката.
Xray использует sendThrough и IPv4; настройка сохраняется при render_config.
Тесты подтверждают прежние форматы и отдельно сетевое переключение.

## Исходная личная версия (история до форка)

В исходной личной версии Endpoint/CONNECT_HOST становятся DNS-именем. Упаковка
QR/vpn:// и ключи не меняются. Выбранный числовой IPv4 используется для сети,
A-запись синхронизируется API. Кеш DNS может требовать ожидания TTL и переподключения.
