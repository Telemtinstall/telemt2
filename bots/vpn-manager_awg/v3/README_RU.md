# Global v3

Сборка для испытаний `global-v3-2026.10.27.4`, основа — неизменённый каталог
`global-vpnbot` (Global v2). Личная версия и работающие серверы не затронуты.
На сервер сборка не устанавливалась; импорт и подключение на устройствах ещё
не проверены. Установка предусмотрена на отдельный чистый Debian 13 / Ubuntu 24+.
Миграция работающего бота из Global v2/личной версии не выполняется.

## Согласованное поведение

- У каждого VPN свой модуль установки и CLI. Исходники установщиков, CLI и
  генераторов AWG/VLESS сохранены без изменений.
- AWG 2.0 и AWG 3.1 можно выбирать независимо. VLESS и Hysteria 2 взаимоисключающие.
- Один вопрос: «VLESS / Hysteria 2?»; ответы `1` / `2`, без выбора по умолчанию.
- Повторяемый `--onlyprotocol` задаёт точный набор и заменяет вопросы выбора.
- INI описывает ответы, `--silent` запрещает вопросы. Неполные обязательные
  настройки или конфликты приводят к понятной ошибке.
- Сначала ядро/headers, потом анкета. До reboot вопросы о VPN/боте не задаются.
  Каждый ответ, включая промежуточный выбор VPN, сразу сохраняется.
- `[server] public_ip = auto` определяет публичный IPv4, назначенный интерфейсу.
- `[server] channel_mbit = auto` выполняет Speedtest. Если замер недоступен,
  заблокирован, завершился ошибкой или вернул некорректные данные — выводится:

```text
Speedtest недоступен или заблокирован.
Установлена скорость по умолчанию: 100 Мбит/с.
Установка продолжается.
```

Результат сохраняется. После reboot ни выбор адреса, ни Speedtest не повторяются.
Явно заданная скорость не вызывает Speedtest. Необязательная установка пакета
speedtest-cli не прерывает установку VPN при недоступности пакета.

## Структура

```text
global-vpnbot-v3/
├── install-global.sh                 # рекомендуемая точка входа
├── silent.example.ini               # все настройки с комментариями
├── installer/
│   ├── install.py                   # порядок этапов
│   ├── ini_config.py                # INI, валидация, план портов
│   ├── questionnaire.py             # вопросы и явный выбор протоколов
│   ├── state.py                     # атомарные контрольные точки
│   ├── system_prepare.py            # ОС, ядро, headers и пакеты
│   ├── detection.py                 # auto IP и Speedtest с fallback 100
│   ├── ports.py                     # занятые TCP/UDP и NAT-резервации
│   ├── execution.py                 # запуск этапов, безопасное продолжение
│   ├── verify.py                    # проверка выбранных CLI/служб
│   ├── bridge.sh                    # сохранённые функции установки бота
│   └── modules/
│       ├── amnezia20.sh
│       ├── amnezia31.sh
│       ├── vless.sh
│       └── hysteria2.sh
├── vpn/
│   ├── amneziawg/                   # исходный установщик и awgctl
│   ├── vless/                       # исходный установщик и vlessctl
│   └── hysteria2/                   # новый установщик и hysteria2ctl

    ├── bot.py                       # быстрый обработчик Telegram
    ├── worker.py                    # отдельный исполнитель задач

```

`bots/vpn-manager_awg/install.sh` сохранён как источник прежних функций v2.
Не запускайте его напрямую для установки v3: используйте `install-global.sh`.

## Запуск

```bash
bash install-global.sh --check
bash install-global.sh --help
sudo bash install-global.sh
sudo bash install-global.sh --onlyprotocol amnezia31 --onlyprotocol hysteria2
```

Значения `--onlyprotocol`: `amnezia20`, `amnezia31`, `vless`, `hysteria2`.
Повторы одного значения игнорируются. `vless` + `hysteria2` запрещены. Уже
работающая/настроенная противоположная служба не удаляется: установщик сообщает
о конфликте и останавливается.

Без ключей/INI: вопрос об установке всех совместимых VPN; при «нет» — два вопроса
да/нет про AWG, затем в любом случае один выбор VLESS/Hysteria 2. «Все» означает
оба AWG и один выбранный VLESS/Hysteria. Для установки только AWG используйте
`--onlyprotocol`; INI при этом можно передать без секции `[protocols]`.

## INI и тихий режим

```bash
cp silent.example.ini install.local.ini
chmod 600 install.local.ini
# Заполните токен, ID админов и домены выбранного протокола.
bash install-global.sh --check --config install.local.ini
sudo bash install-global.sh --silent --config install.local.ini
```

Секреты не публикуйте. В релиз включается только `silent.example.ini`, остальные
INI-файлы исключены из сборщика. Реальные секреты требуют прав 0600 и владельца
текущего пользователя или пользователя, вызвавшего sudo.

Приоритет ответов: CLI → переменные окружения → INI → сохранённые ответы.
После начала изменений VPN менять план запрещено. Противоречие наборов VPN между
INI и `--onlyprotocol` вызывает ошибку, а не молчаливую замену.

В INI `amnezia20/amnezia31` — `yes/no`, `vless_or_hysteria2` — `1/2`.
Секции обоих протоколов могут присутствовать одновременно: работает только выбранная.
`--config` сам по себе не включает тихий режим: нужен `--silent`. При продолжении
сохранённый тихий режим также сохраняется.

`--check` проверяет пакет, входные значения и внутренние конфликты портов без
изменений системы. `--check --silent --config ...` дополнительно требует заполнить
обязательные ответы. Занятые порты проверяются только на целевом сервере при
установке; локальная проверка не исследует удалённый сервер.

## Этапы и продолжение

1. Проверка пакета, ОС, параметров и старой установки; запись переданных настроек.
2. Если Python 3 отсутствует, оболочка сначала устанавливает его без вопросов.
   Затем подготовка ядра >= 6.7 и headers перед анкетой. Если ключами выбраны только
   VLESS/Hysteria, ненужная для AWG подготовка пропускается.
3. Если нужно загрузить новое ядро — завершение с кодом 75 и командой продолжения.
   Выполните reboot самостоятельно. Команда сохраняет путь `--state-file` и не
   содержит секретов. Автоперезагрузки нет.
4. Подготовка общих пакетов; необязательная попытка установить speedtest-cli.
5. Анкета: VPN, IP/auto, первый пользователь, ID админов, токен, скорость/auto,
   порты, параметры выбранного протокола и режима обфускации.
6. Проверка занятых портов и назначенного адреса; разрешение auto; сохранение
   конкретных значений и причин fallback.
7. Резервные копии; установка только выбранных модулей; установка бота и worker.
8. Проверка реестра выбранных протоколов, JSON-ответов CLI, состояния каждой
   выбранной службы, бота, worker и обоих таймеров.

Ответы хранятся в `/root/.vpnbot-global-v3.json`, права 0600, атомарная запись с
fsync. Успешные этапы не повторяются. Прерванные операции пакетов и финальную
проверку можно безопасно повторить. Если процесс оборвался внутри установки VPN
или бота, автоматический повтор запрещён до сверки сервера. После проверки:

```bash
sudo bash install-global.sh --resolve-stage hysteria2 --stage-result done
# либо --stage-result retry, если проверено, что повтор допустим
# Для нестандартного файла добавьте тот же --state-file /путь/к/состоянию.json.
```

Команда только фиксирует проверенный итог и печатает команду продолжения.
Не редактируйте контрольные точки или базу очереди вручную ради обхода проверки.

## Порты и Hysteria

Проверяются TCP/UDP отдельно, IPv4/IPv6 слушатели, NAT-диапазоны и наборы nftables,
а также legacy iptables NAT при наличии. Служебные порты тоже резервируются:
VLESS API TCP 10085, mask backend TCP 12710, ACME TCP 80, Hysteria API TCP 19090.
Пример: VLESS TCP 443 и AWG UDP 443 совместимы, AWG UDP 443 и Hysteria UDP 443 — нет.
При конфликте тихий режим выдаёт ошибку без диалога и не запускает VPN-модули.

Hysteria: `none` (HTTP/3 + сайт), `salamander`, `gecko`. Выбор обязательный.
CLI `/usr/local/sbin/hysteria2ctl`, служба `hysteria2.service`, отдельная авторизация
`hysteria2-auth`, файлы `/etc/hysteria/` с закрытыми правами. Добавление пользователя
не перезапускает VPN; при удалении вызывается `/kick`. API — loopback с секретом.
Бинарник закреплён на `app/v2.13.0`, проверяется официальный `hashes.txt`.

Для встроенного ACME нужны правильные A-записи и доступный извне TCP 80. Эта
IPv4-сборка отклоняет AAAA домена Hysteria. Чужие веб-серверы не останавливаются.
Внешний firewall провайдера настраивается администратором. При активном UFW
разрешаются выбранный UDP-порт и TCP 80.

Установщик не показывает QR/ключи. В боте доступны ссылка, QR и YAML для Clash.
JSON в YAML-файле является допустимым YAML. Поддержку Gecko и его параметров
нужно проверять в конкретной версии приложения на устройстве.

Сохраняющееся ограничение: при наличии Hysteria смена IP/домена из бота заблокирована
до реализации общей операции с обновлением TLS. При наборе AWG/VLESS прежний
механизм домена/IP сохраняется.

## Очередь и согласованность

`jobs.sqlite3` (0600) хранит намерения и результаты; реальные VPN-конфигурации
меняют только `awgctl`, `awg3ctl`, `vlessctl`, `hysteria2ctl`.
`vpnbot-worker.service` выполняет одну задачу за раз. Навигация не ждёт CLI.
Создание/удаление, QR, отчёты, live-списки и смена IP/домена — в общей очереди.
Права повторно проверяются перед выполнением и выдачей результата. Восстановление
сохранённого состояния служб при запуске также идёт через очередь, а не из frontend бота.
Удаление сначала подтверждается на сервере, затем очищаются записи доступа/трафика.

Повторная доставка одного update не создаёт вторую задачу; два отдельных нажатия
создают два запроса. Недоступность Telegram повторяет отправку результата, а не
серверную команду. Явный отказ CLI до изменения состояния (например, занятое имя
Hysteria) отмечается как ошибка и не блокирует следующую задачу. Возможен повтор сообщения при сбое после его отправки, но до
отметки SQLite. Подтверждённые отправки очищаются от содержимого профилей.

Прерванные чтения возвращаются в очередь. Прерванные изменения получают
`needs_review` и блокируют последующие задачи до сверки сервера через CLI.
После проверки используется штатная команда, а не ручное редактирование SQLite:

```bash
cd /root/vpnbot
python3 worker.py --resolve 42 --result done
# либо --result failed
```

## Проверка и откат

Тесты из `bots/vpn-manager_awg`: `python3 -m unittest discover -s tests -q`.
Они проверяют очередь, сбои, 20 параллельных запросов, режимы Hysteria, неизменность
старых генераторов, INI, auto, fallback100 и весь сценарий установщика со
заглушками системных команд. Это не установка на настоящем Linux-сервере.
PNG через qrencode, импорт и подключение на устройствах проверяются отдельно.

Резервные копии — `/root/vpnbot-backups/`. Откат требует согласованного восстановления
CLI, конфигураций и бота; копирование одной старой базы поверх нового сервера
не является откатом. Локальная точка возврата — неизменённый `global-vpnbot`.
Публикация v3 размещается отдельно; на серверах сборка пока не развёртывалась.

Официальные параметры Hysteria:
https://v2.hysteria.network/docs/advanced/Full-Server-Config/
https://v2.hysteria.network/docs/advanced/Traffic-Stats-API/

## Публикация v3 на GitHub

Отдельный каталог репозитория: `bots/vpn-manager_awg/v3/`.
Тег сборки: `global-v3-2026.10.27.4`. Существующие v2 и основной установщик не заменяются.
Отдельная команда для подготовленного Debian 13 / Ubuntu 24+ (root):

```bash
curl -fL https://raw.githubusercontent.com/Telemtinstall/telemt2/global-v3-2026.10.27.4/install-v3.sh -o /root/install-v3.sh
bash /root/install-v3.sh --check
bash /root/install-v3.sh
```

Для предварительной установки инструментов загрузки:
`apt-get update` и `apt-get install -y ca-certificates curl python3`.
Загрузчик получает закреплённый тег, извлекает только каталог v3, запрещает
symlink/path traversal и проверяет SHA256SUMS перед запуском. Пакет хранится в
`/root/vpnbot-global-v3-2026.10.27.4`; повторная команда использует эту же копию.
Находясь внутри полного пакета, `bash install-v3.sh` вызывает локальный установщик.

GitHub Actions проверяет пакет и тесты в Debian 13 и Ubuntu 24.04, включая реальное
создание PNG Hysteria через qrencode. Проверки установочных этапов используют
подставные системные команды: установка ядра/DKMS, запуск VPN и подключение устройств
по-прежнему должны проверяться на отдельном сервере.
