# Исправления 2026.09.05-audit-fixes.1

Область: последняя версия vpn-manager_awg; развёртывание только frp.netnum.ru.
Контроллеры awgctl/awg3ctl/vlessctl и алгоритмы формирования QR не заменяются.

Исправлено:
- Кнопки профилей используют имя, а ответы контроллера проверяются до выдачи секрета.
- Изменение ключа/UUID уже зарегистрированного профиля отзывает старые права и приглашения. При первом переходе текущие ключи становятся исходной точкой проверки.
- Доступ отзывается до удаления VPN; ошибка очистки истории не сохраняет доступ. Если удаление контроллером завершится ошибкой, доступ к боту потребуется выдать заново.
- Короткие сохраняемые кнопки привязаны к чату; операции изменения одноразовые и действуют 10 минут. Старые кнопки требуют /menu.
- Очередь Telegram сохраняется в SQLite. В каждом чате сохраняется порядок; одновременно работают до четырёх чатов. После аварии начатая внешняя операция не повторяется автоматически, её ID остаётся в журнале для проверки.
- Общее блокирование доступа к истории между процессами; транзакционная запись счётчиков; проверка идентичности файла БД перед использованием. Автоматическое удаление истории по снимку контроллера отключено.
- Сбор каждую минуту и перед выключением протокола. Ошибка одного протокола не останавливает сбор остальных.
- Пустой снимок отключённого протокола не вызывает контроллер повторно; ошибки отчётов изолированы.
- Персональные отчёты читают БД выбранного пользователя. Месяц определяется по UTC.
- Максимум, текущее значение и P95 канала вычисляются по исходным измерениям, до прореживания графика.
- Настройки проверяются при запуске; отмена добавления администратора работает, кандидат истекает через 10 минут.
- HTML разбивается с сохранением тегов и сущностей; размер учитывает UTF-16.
- Состояние протокола сохраняется до изменения службы и проверяется после; ошибка отката явно регистрируется.
- Резервное копирование SQLite использует backup API с integrity_check. Установщик сохраняет существующие .env и servers.json; новые пути контроллеров соответствуют параметрам установки.
- Исправлены ограничение имени первичного клиента, правило logrotate и документация резервирования.

Практические ограничения:
- Неснятый трафик до сброса счётчиков восстановить невозможно. Минутный сбор уменьшает окно потери, но не даёт точности биллинга при авариях; дневные суммы относятся к моменту снимка UTC.
- Импорт QR в реальные приложения на физических iPhone/Android автоматически не проверяется. На frp проверено совпадение QR-полезной нагрузки старой и новой версии для AWG 2.0 и 3.1, все три варианта. У VLESS нет существующих клиентов для живого теста.
- Коллизия нестандартных имён БД обнаруживается с отказом в доступе; автоматическое слияние или переименование чужой истории не производится.
- Полные CSV намеренно охватывают всю сохранённую историю. Большие отчёты могут занимать время.

Проверка: python3 -m unittest discover -s tests -v
