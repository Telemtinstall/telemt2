# VPN Bot Full Installer v2

Краткая русская инструкция по установке, обновлению и работе с меню:
[USAGE_RU.md](USAGE_RU.md).

Это актуальная версия VPN Manager, которая заменяет прежнего бота,
поддерживавшего только AmneziaWG. История старой реализации сохраняется в Git,
а новый установщик поддерживает параллельно AmneziaWG 2.0,
AmneziaWG 3.1 и VLESS в одном интерфейсе.

## Быстрый запуск на новом сервере

Войдите на Debian 13+ или Ubuntu 22.04+ как `root` и вставьте весь блок.
Команда сама установит `curl` и корневые сертификаты, скачает загрузчик и
запустит его. `sudo` на чистом сервере не требуется:

```bash
apt-get update &&
apt-get install -y --no-install-recommends ca-certificates curl &&
curl -fsSL https://raw.githubusercontent.com/Telemtinstall/telemt2/main/bots/vpn-manager_awg/install_bot.sh -o /tmp/install_bot.sh &&
chmod +x /tmp/install_bot.sh &&
/tmp/install_bot.sh
```

Загрузчик скачает или безопасно обновит репозиторий в `/root/telemt2`, проверит
контрольные суммы и передаст управление основному установщику. Тот скрыто
запросит `BOT_TOKEN`, запросит один или несколько Telegram ID администраторов
через запятую, проведёт аудит компонентов и запустит службы. Если в локальном
клоне есть несохранённые изменения, автоматическое обновление остановится, не
перезаписывая их. Для первоначальной загрузки `install_bot.sh` самостоятельно
ставит только `git` и корневые сертификаты, если их ещё нет.

Перед изменением сервера основной установщик показывает установленные и
доступные версии, а затем задаёт два вопроса:

```text
Установить/обновить дополнительное ПО бота (Python, Pillow, logrotate, Speedtest)? [yes]:
Установить/обновить AmneziaWG 2.0, AmneziaWG 3.1 и VLESS, совместимые с ботом? [yes]:
```

На первый вопрос установщик проверяет `git`, `ca-certificates`, Python 3,
Pillow, шрифты для графиков, `logrotate` и `speedtest-cli`. Ответ `yes`
устанавливает отсутствующие пакеты и доступные обновления. При ответе `no`
установщик ничего не обновляет, но остановится, если обязательного пакета нет.

На второй вопрос ответ `yes` устанавливает отсутствующие протоколы и обновляет
`awgctl`/`awg3ctl`/`vlessctl` до версий из этого репозитория, не пересоздавая рабочие VPN,
когда сами протоколы уже исправны. Ответ `no` разрешён только тогда, когда все три
управляющих скрипта уже полностью совпадают с совместимой версией.

Если хотя бы одного протокола нет, установщик один раз спрашивает общие
параметры:

```text
Публичный IP/host для всех VPN [определённый IP]:
Имя первого пользователя во всех VPN [vpnuser1]:
```

После этого штатные установщики запускаются без повторных вопросов:
AmneziaWG 2.0 получает DNS-профиль на UDP `1234`, отдельный AmneziaWG 3.1 —
AWG 3.x-профиль на UDP `1235`, VLESS — direct WebSocket на TCP `443`.
Один host и одно начальное имя используются для всех трёх вариантов.

### Журнал и продолжение прерванной установки

Весь вывод основного установщика записывается в
`/var/log/vpnbot-install.log`. В журнал не записывается значение `BOT_TOKEN`:
оно вводится как пароль без отображения. Журнал ежедневно ротируется,
сжимается и хранится максимум 7 дней.

После каждого завершённого крупного этапа его идентификатор сохраняется в
`/root/.install_vpnbot.state`, а несекретные ответы — в
`/root/.install_vpnbot.config`. Если SSH-соединение оборвалось или команда
завершилась с ошибкой, достаточно снова запустить `install_bot.sh`. Установщик
покажет выполненные этапы и продолжит со следующего. Вложенные установщики
AmneziaWG и VLESS также используют собственные контрольные точки. После полной
успешной установки временные контрольные точки VPN-бота удаляются.

Повторный запуск той же команды обновляет каталог из GitHub и переустанавливает
бота с созданием резервной копии текущего `/root/vpnbot`.

Для ручного запуска перенесите каталог `bots/vpn-manager_awg` на чистый Debian
13+ или Ubuntu 22.04+ и выполните внутри него:

```bash
cd vpn-manager_awg
chmod +x install.sh
./install.sh --dry-run
./install.sh
```

По умолчанию устанавливаются:

- AmneziaWG 2.0 с DNS-профилем, UDP 1234;
- AmneziaWG 3.1-совместимый профиль на отдельном интерфейсе `awg3`, UDP 1235;
- VLESS/Xray direct WebSocket, TCP 443;
- multi-protocol Telegram-бот с reply-меню;
- отдельная SQLite-база каждого VPN-пользователя;
- центральная SQLite-база прав и одноразовых приглашений;
- суточные и помесячные CSV по серверу и выбранному пользователю;
- PNG-графики трафика по дням в МБ и по месяцам в ГБ;
- ежедневный сбор трафика в 23:59 UTC;
- ежеминутный пассивный мониторинг общей загрузки канала VDS;
- административный экран CPU/RAM/disk/network;
- ручной Speedtest из раздела `Админ` с JSON-скриптом;
- journald до 200 МБ и хранение логов максимум 7 дней;
- Speedtest для подбора `SERVER_CHANNEL_MBIT`.

Аватар бота сохранён в `assets/`: PNG используется как исходник, а JPG
`vpn-bot-avatar-640-v2.jpg` подготовлен для загрузки через метод Telegram Bot
API `setMyProfilePhoto`.

Перед заменой существующего `/root/vpnbot` автоматически создаётся резервная
копия в `/root/vpnbot-backups`. Секреты записываются только в `.env` с правами
`0600`.

В меню `Админ` доступны `Состояние сервера` и `Замер скорости`. Второй пункт
запускает `/usr/local/sbin/vpn-speedtest -j`, временно загружает канал и после
завершения показывает download, upload, ping, тестовый узел и процент от
`SERVER_CHANNEL_MBIT`. Одновременно может выполняться только один замер.

Автоматический direct-режим:

```bash
BOT_TOKEN='123456:token' \
ADMIN_BOT='123456789,987654321' \
SERVER_CHANNEL_MBIT=200 \
ASSUME_YES=1 \
./install.sh --auto --vless-direct
```

Для VLESS с HTTPS-маскировкой используйте `--vless-mask`; в автоматическом
режиме дополнительно задайте `PUBLIC_HOST` и остальные параметры, которые
требует штатный `telemt2/vpn/vless/install_vless.sh`.

# VPN Bot: AmneziaWG 2.0 + AmneziaWG 3.1 + VLESS

Версия: `2026.09.03-admin-settings.1`

Этот документ описывает рабочую версию Telegram-бота. Администраторы из `.env`
управляют локальными AmneziaWG 2.0, AmneziaWG 3.1 и VLESS/Xray, а обычные Telegram-пользователи
могут получить доступ только к выданным им VPN-профилям. Трафик каждого
VPN-пользователя хранится в независимой SQLite-базе.

## 1. Общая схема

```text
Telegram admin
  -> Telegram Bot API polling
  -> /root/vpnbot/bot.py
     -> выбор протокола
     -> AmneziaWG 2.0 -> /usr/local/sbin/awgctl
     -> AmneziaWG 3.1 -> /usr/local/sbin/awg3ctl
     -> VLESS          -> /usr/local/sbin/vlessctl

Telegram VPN user
  -> одноразовый /start claim_<token>
  -> /root/vpnbot/access.sqlite3
  -> только свои AmneziaWG/VLESS настройки

Daily systemd timer (23:59 UTC)
  -> /root/vpnbot/traffic_collect.py
  -> текущие счётчики awgctl/vlessctl
  -> отдельный SQLite-файл каждого пользователя
```

Бот не использует webhook. Обновления Telegram получает long polling-процесс `vpnbot.service`.

## 2. Главное меню и сценарии

После `/start` или `/menu` бот предлагает протокол:

1. `AmneziaWG 2.0`
2. `AmneziaWG 3.1`
3. `VLESS`
4. `Админ`

После выбора протокола доступны:

- создание пользователя;
- список пользователей;
- проверка online;

Меню протокола состоит из четырёх reply-кнопок в два ряда: создание,
список, online и возврат в главное меню. Общий трафик и CSV-отчёты перенесены
в раздел `Админ → Трафик`. Одна кнопка без дополнительного выбора протокола
отправляет общие суточный и помесячный PNG-графики, а также два CSV-файла
сначала для AmneziaWG, затем для VLESS.
Трафик отдельного пользователя доступен администратору из его inline-карточки.
Владелец выданного профиля получает такую же кнопку `Мой трафик`, но графики
и CSV фильтруются только по его VPN-пользователю.
Верхний уровень админки содержит четыре кнопки: `Состояние сервера`, `Трафик`,
`Настройки`, `Назад`. При входе в `Трафик` бот отправляет отчёты, затем показывает
сетку `Замер скорости`, `Загрузка канала`, `Кто онлайн`, `Назад`.

В `Настройки → Протоколы` каждый вариант имеет сохранённое состояние. Отключение
останавливает и выключает systemd-службу, скрывает протокол в главном меню, но
не удаляет клиентов, ключи, права и SQLite-базы. После включения прежние
профили снова работают. В `Настройки → Администраторы` доступны добавление по
ID или пересланному сообщению, список и удаление; администраторы из `.env`
удалению через бот не подлежат.

Главное меню, меню протокола, создание, online/трафик, обновление, возврат и
переход в главное меню реализованы Telegram reply-кнопками. Inline-кнопки
появляются только в списке VPN-пользователей и в карточке выбранного
пользователя.

Reply-кнопки располагаются компактно по две в строке: четыре кнопки образуют
сетку `2×2`, три — две в верхнем ряду и одну в нижнем. Для пяти кнопок
используется схема `2+2+1`.

Правила навигации:

- `Главное меню` из любого раздела сбрасывает текущий ввод и возвращает к выбору протокола;
- `Назад` возвращает на один логический уровень;
- `Отмена` доступна при вводе имени и отменяет создание;
- `Обновить` перерисовывает текущий список, online или трафик;
- старое сообщение с inline-кнопками не является главным меню и не хранит навигационное состояние.

После обновления бота администратору нужно один раз отправить `/start`, чтобы
Telegram заменил ранее показанную клавиатуру новой.

### Администрирование и состояние сервера

Reply-кнопка `Админ` открывает раздел с кнопкой `Состояние сервера`. Бот
запускает `/usr/local/sbin/server-status -j`, проверяет JSON и показывает:

- текущую загрузку CPU и load average за 1/5/15 минут;
- количество процессорных ядер;
- использованную и доступную память;
- заполнение корневого раздела `/`;
- текущую скорость приёма и передачи основного сетевого интерфейса;
- объём принятого и переданного трафика с момента запуска;
- новые сетевые ошибки и отброшенные пакеты только за текущий замер;
- uptime и UTC-время измерения.

CPU и сеть измеряются одновременно в течение двух секунд. Для CPU, памяти и
диска используются статусы: зелёный до 60%, жёлтый от 60% до 85%, красный от
85%. Кнопка `Обновить` выполняет новый замер, `Назад` возвращает в раздел
администрирования.

Суммарный трафик показывается с момента запуска, но сетевые ошибки и
отброшенные пакеты вычисляются только за текущий двухсекундный замер. Если за
это время новых ошибок нет, строка о них не показывается.

Кнопка `Замер скорости` запускает отдельный JSON-скрипт
`/usr/local/sbin/vpn-speedtest -j`. Во время теста канал временно загружается.
После завершения бот показывает download/upload в Мбит/с, ping, тестовый узел,
переданный объём и процент от `SERVER_CHANNEL_MBIT`. Кнопка `Обновить`
запускает новый тест, `Назад` возвращает в раздел администрирования.

Кнопка `Загрузка канала` не запускает Speedtest и не создаёт тестовый трафик.
Она строит PNG-график по пассивным системным счётчикам основного интерфейса
VDS. Доступны периоды `1 час`, `24 часа`, `7 дней` и `30 дней`; синим показан
приём, оранжевым — передача. Бот также выводит текущую, среднюю, максимальную
скорость, p95 и новые ошибки/потери за период.

### Создание пользователя

Администратор вводит имя или просит создать имя автоматически. Допустимы латинские буквы, цифры, точка, дефис и `_`.

Для AmneziaWG бот возвращает:

- отдельные кнопки `QR для iPhone` и `QR для Android`, отправляющие обычный
  `.conf` QR для приложения AmneziaWG;
- отдельную кнопку `QR AmneziaVPN` с native payload;
- копируемый ключ подключения `vpn://…` для импорта в AmneziaVPN;
- файл `.conf`;
- текст конфигурации для роутера.

Для VLESS бот возвращает:

- QR;
- VLESS-ссылку.

Сразу после создания пользователя бот создаёт его отдельную SQLite-базу. Пользователи, созданные вне бота через `awgctl` или `vlessctl`, получают базу при следующем ежедневном сборе.

При ежедневном сборе список VPN-пользователей сверяется со списком доступных
счётчиков. Если оба источника успешно получены и полностью совпадают, базы
отсутствующих пользователей удаляются вместе с SQLite sidecar-файлами. При
любом расхождении автоматическая очистка пропускается, чтобы не потерять
историю из-за временной ошибки управляющего скрипта.

### Список, online и удаление

Список формируется из JSON-ответов локального управляющего скрипта. Для AWG online определяется по свежему handshake. Для VLESS используется `vlessctl -j online` и статистика Xray.

Удаление всегда требует подтверждения. После успешного удаления VPN-пользователя
бот удаляет его персональную SQLite-базу и служебные файлы SQLite
(`-wal`, `-shm`, `-journal`). История трафика и отчёты пользователя не
сохраняются. Одновременно удаляются права доступа к боту и все приглашения
этого профиля. Системные журналы при этом не изменяются.

## 3. Конфигурация протоколов

Рабочий файл `/root/vpnbot/servers.json`:

```json
[
  {
    "id": "amneziawg",
    "title": "AmneziaWG 2.0",
    "protocol": "amneziawg",
    "transport": "local",
    "command": "/usr/local/sbin/awgctl",
    "service": "awg-quick@awg0.service"
  },
  {
    "id": "amneziawg3",
    "title": "AmneziaWG 3.1",
    "protocol": "amneziawg",
    "transport": "local",
    "command": "/usr/local/sbin/awg3ctl",
    "service": "awg-quick@awg3.service"
  },
  {
    "id": "vless",
    "title": "VLESS",
    "protocol": "vless",
    "transport": "local",
    "command": "/usr/local/sbin/vlessctl",
    "service": "xray.service"
  }
]
```

Все три варианта находятся на том же сервере, поэтому используется `transport: local`.

## 4. `.env` и авторизация

Файл: `/root/vpnbot/.env`, права: `0600`.

```env
BOT_TOKEN=123456:replace-me
ADMIN_BOT=123456789,987654321
AWGCTL=/usr/local/sbin/awgctl
AWG3CTL=/usr/local/sbin/awg3ctl

BOT_TITLE=Личный VPN-бот
PRIVATE_ONLY=1
ONLINE_WINDOW_SECONDS=180
VLESS_ONLINE_INTERVAL_SECONDS=3
POLL_TIMEOUT=45
REQUEST_TIMEOUT=75
MAX_MESSAGE=3900
LOG_LEVEL=CRITICAL

SERVERS_CONFIG=/root/vpnbot/servers.json
TRAFFIC_DB_DIR=/root/vpnbot/traffic-data
TRAFFIC_TIMEZONE=UTC
ACCESS_DB_PATH=/root/vpnbot/access.sqlite3
ACCESS_INVITE_HOURS=24

SERVER_STATUS_COMMAND=/usr/local/sbin/server-status
SERVER_CHANNEL_MBIT=200
SPEEDTEST_COMMAND=/usr/local/sbin/vpn-speedtest
SPEEDTEST_TIMEOUT=210
```

`ADMIN_BOT` поддерживает один или несколько числовых Telegram ID через запятую
и предоставляет полный административный доступ. Права обычных пользователей
читаются из `ACCESS_DB_PATH` при каждом действии. При `PRIVATE_ONLY=1` бот не
выдаёт конфигурации и ключи в групповых чатах.

`SERVER_CHANNEL_MBIT` задаёт номинальную пропускную способность канала в
Мбит/с. Она используется только для вычисления процента загрузки; фактическая
скорость берётся из `/proc/net/dev`.

Перед установкой значение следует определить контрольными замерами
`speedtest-cli` и округлить вверх до номинальной скорости канала с запасом.

## 5. Пользовательский доступ к VPN-профилям

В карточке VPN-пользователя администратор нажимает `Предоставить доступ`. Бот
создаёт одноразовую ссылку `https://t.me/<bot>?start=claim_<token>` сроком на
`ACCESS_INVITE_HOURS`. В базе хранится только SHA-256 токена.

После первого успешного `/start` ссылка становится недействительной, а
VPN-профиль привязывается к постоянному Telegram `from.id`. Карточка
администратора сразу показывает:

```text
Доступ к боту: выдан
Получатель: Иван Петров (@ivan_petrov)
Telegram ID: 123456789
Активирован: 2026-08-09 19:15:00 UTC
```

Если ссылка ещё не использована, карточка показывает состояние ожидания и
UTC-срок действия. Повторное создание ссылки аннулирует прежние ожидающие
приглашения.

Один VPN-профиль может иметь одного активного владельца. Один Telegram ID
может одновременно владеть несколькими профилями, например AmneziaWG и VLESS.
Обычный пользователь видит меню `Мои VPN` и может только повторно получить
действующие настройки:

- AmneziaWG: QR для iPhone/Android, QR и ключ для AmneziaVPN, `.conf`, текст
  для роутера;
- VLESS: QR и VLESS-ссылку.

Создание, удаление, чужие профили, трафик, online и админка ему недоступны.
Каждая команда и callback повторно проверяют пару `server_id + vpn_user_name`
в SQLite; скрытие кнопок не используется как механизм безопасности.

Кнопка `Отозвать доступ` действует немедленно. `Передать другому` отзывает
текущего владельца и создаёт новую одноразовую ссылку после подтверждения.
После активации все администраторы получают уведомление с именем, username,
Telegram ID, протоколом и VPN-именем получателя.

Центральная база:

```text
/root/vpnbot/access.sqlite3
```

Она содержит `access_grants` и `invite_tokens`, использует UTC `TIMESTAMP`,
WAL, `busy_timeout`, `secure_delete` и транзакцию `BEGIN IMMEDIATE` при
активации. Основной файл имеет права `0600`.

При удалении VPN-пользователя удаляются его база трафика, активное право и все
ожидающие/использованные приглашения. Системные журналы не изменяются.

## 6. Учёт трафика

Каталог баз:

```text
/root/vpnbot/traffic-data/
```

Формат имени:

```text
<server_id>__<vpn_user>.sqlite3
```

Примеры:

```text
amneziawg__anna.sqlite3
vless__client1.sqlite3
```

Права каталога `0700`, каждой базы `0600`.

### Схема SQLite

Каждая база содержит три таблицы.

`identity`:

- `server_id` — идентификатор сервера/протокола;
- `protocol` — `amneziawg` или `vless`;
- `user_name` — имя VPN-пользователя;
- `created_at TIMESTAMP` — UTC-время создания базы.

`state`:

- последние системные upload/download-счётчики;
- время последнего снимка;
- используется для вычисления дельты.

`daily_usage`:

- `day DATE` — календарный день UTC;
- `upload_bytes INTEGER`;
- `download_bytes INTEGER`;
- `total_bytes INTEGER`;
- `captured_at TIMESTAMP` — UTC-время снимка.

В базе трафик всегда хранится целым числом байтов. Преобразование в человекочитаемый формат или мегабайты выполняется только при показе и экспорте.

### Вычисление суточного трафика

Управляющие скрипты возвращают накопительные системные счётчики. Для каждой метрики используется формула:

```text
если current >= previous:
    delta = current - previous
иначе:
    delta = current
```

Вторая ветка обрабатывает сброс счётчика после перезапуска `awg0`, Xray или сервера. Отрицательный трафик в базу не попадает.

Повторный запуск сборщика в тот же день безопасен: новая дельта добавляется к существующей строке этого UTC-дня.

### Ежедневный сбор

Юниты:

```text
/etc/systemd/system/vpnbot-traffic.service
/etc/systemd/system/vpnbot-traffic.timer
```

Таймер запускает сборщик каждый день в `23:59 UTC` и имеет `Persistent=true`. Проверка:

```bash
systemctl status vpnbot-traffic.timer
systemctl list-timers vpnbot-traffic.timer
journalctl -u vpnbot-traffic.service
```

Ручной снимок:

```bash
systemctl start vpnbot-traffic.service
```

## 7. Графики, месячный трафик и CSV

Экран `Трафик` показывает текущий UTC-месяц по каждому пользователю и общий итог. В сумму входят:

- сохранённые суточные строки текущего месяца;
- текущая дельта после последнего снимка, прочитанная напрямую из AWG/Xray.

Перед CSV бот отправляет два PNG-графика. Суточный график показывает каждый
UTC-день текущего месяца в мегабайтах; подписи оси стоят на днях
`1, 5, 10, 15, 20, 25, 30` и на текущем дне. Месячный график показывает
последние 12 UTC-месяцев в гигабайтах. У администратора суммируются все
пользователи выбранного протокола, у владельца профиля используется только
его персональная SQLite-база и текущая дельта.

Кнопка отчёта также отправляет два файла:

```text
traffic_<protocol>_daily.csv
traffic_<protocol>_monthly.csv
```

Суточный CSV:

```text
date,server_id,protocol,user,upload_mb,download_mb,total_mb
```

Месячный CSV:

```text
month,server_id,protocol,user,upload_mb,download_mb,total_mb
```

CSV кодируется в UTF-8 с BOM для корректного открытия в Excel. Значения округляются до трёх знаков, `1 MB = 1,048,576 bytes`. Исходные SQLite-данные остаются в байтах без округления.

В карточке выбранного пользователя кнопка `Трафик пользователя` открывает его
текущие показатели и reply-кнопку `Скачать CSV пользователя`. В профиле
обычного владельца кнопка `Мой трафик` сразу отправляет два персональных
графика и два отфильтрованных файла:

```text
traffic_<protocol>_<user>_daily.csv
traffic_<protocol>_<user>_monthly.csv
```

Первый содержит строки по UTC-дням, второй — суммы по UTC-месяцам. В обоих
файлах присутствуют данные только выбранного VPN-пользователя.

## 8. Ежеминутный мониторинг канала VDS

`vpnbot-channel.timer` запускает `channel_collect.py` каждую минуту. Скрипт
читает накопительные счётчики `/sys/class/net/<interface>/statistics`,
вычисляет дельту относительно предыдущего запуска и записывает её в
`/root/vpnbot/server-metrics.sqlite3`.

В SQLite сохраняются UTC `TIMESTAMP`, фактический интервал, байты, пакеты,
ошибки и отброшенные пакеты отдельно для приёма и передачи. Скорость в
Мбит/с вычисляется при построении графика; исходные значения остаются в
байтах. Перезагрузка VDS, смена интерфейса или сброс счётчика создают новую
базовую точку без отрицательных значений. Минутные строки хранятся 90 дней.

Speedtest в этом сборщике не используется. Минутные строки старше 90 дней
удаляются автоматически. После удаления выполняются WAL checkpoint и
`VACUUM`, поэтому освобождённое место возвращается файловой системе; тяжёлая
операция запускается максимум один раз в UTC-сутки.

## 11. Логи и хранение

Сам бот пишет в journald. На рабочем сервере настроено:

- хранение journald максимум 7 дней;
- лимит journald 200 МБ;
- ежедневный logrotate;
- максимум 7 архивов и `maxage 7`;
- сжатие старых файловых логов.

Настройка ротации является серверной политикой и не входит в архив исходников бота.

## 12. Резервное копирование и восстановление

Для полного переноса нужны:

```text
/root/vpnbot/.env                     секреты, переносить отдельно
/root/vpnbot/servers.json             список протоколов
/root/vpnbot/traffic-data/            история трафика
/etc/amnezia/amneziawg/               сервер и клиенты AWG
/usr/local/etc/xray/                   VLESS/Xray и пользователи
```

Архив релиза намеренно не содержит `.env`, SQLite-данные, UUID, VPN-конфиги и приватные ключи.

Перед обновлением:

```bash
cp -a /root/vpnbot /root/vpnbot-backup-$(date -u +%Y%m%dT%H%M%SZ)
```

После восстановления исходников:

```bash
python3 -m py_compile /root/vpnbot/bot.py /root/vpnbot/traffic_collect.py /root/vpnbot/app/*.py
systemctl daemon-reload
systemctl enable --now vpnbot.service vpnbot-traffic.timer
systemctl start vpnbot-traffic.service
```
