# VPN Manager — Global v4

## Установка: скопируйте весь блок

Войдите **под root на новый чистый сервер Debian 13 / Ubuntu 24+** и выполните:

```bash
apt-get update &&
apt-get install -y --no-install-recommends ca-certificates curl python3 &&
curl --fail --show-error --location --proto '=https' --tlsv1.2 --retry 3 https://raw.githubusercontent.com/Telemtinstall/telemt2/main/install-v4.sh -o /root/install-v4.sh &&
chmod 700 /root/install-v4.sh &&
/root/install-v4.sh
```

`install-v4.sh` лежит **в корне репозитория**. Он скачивает закреплённую копию
`bots/vpn-manager_awg/v4`, безопасно распаковывает её, проверяет контрольные суммы
и запускает установку. `chmod 700` разрешает запуск и чтение файла только root.
Сам бот устанавливается в `/root/vpnbot`; скачанный пакет хранится отдельно в
`/root/vpnbot-global-v4-2026.11.15.5`.

Повторный запуск этой версии использует уже скачанный пакет и сохранённые ответы:

```bash
/root/install-v4.sh
```

Это **новая установка**, а не миграция существующей Personal/v2/v3. Загрузчик
не обновляет работающего бота автоматически. Установщик отклоняет чужие существующие
VPN-конфигурации. Не запускайте на работающем сервере вместо штатного обновления.

Если curl уже установлен, достаточно трёх последних команд из первого блока.
Альтернатива с wget (при наличии wget, Python 3 и корневых сертификатов):

```bash
wget https://raw.githubusercontent.com/Telemtinstall/telemt2/main/install-v4.sh -O /root/install-v4.sh &&
chmod 700 /root/install-v4.sh &&
/root/install-v4.sh
```

## Что подготовить

- Debian 13 или Ubuntu 24+ с systemd, доступ root и рабочие репозитории apt.
  Для сборки AWG нужны подходящее ядро, headers и возможность загрузки модуля.
- Публичный IPv4, назначенный сетевому интерфейсу. Сборка рассчитана на один внешний
  интерфейс с одним или несколькими публичными IPv4, а не на частный адрес за NAT.
- Токен собственного Telegram-бота от BotFather и числовой Telegram ID администратора.
  Для нескольких администраторов — ID через запятую. Токен вводится скрыто.
- При использовании домена — возможность вручную менять его A-запись.
- Доступ сервера в Интернет: GitHub, apt, Telegram и необходимые источники пакетов.
  Для HTTPS-режимов VLESS/Hysteria нужен выпуск сертификата.
- Открытые выбранные VPN-порты в firewall провайдера. Для ACME нужен входящий TCP 80.
  Внешний firewall установщик за вас не меняет.

Для малой RAM при нехватке swap установщик создаёт 1 ГиБ swap. Для этого требуется
минимум 2 ГиБ свободного места; существующий достаточный swap повторно не создаётся.
Токены, ключи клиентов и файл ответов не отправляйте в публичные сообщения/репозиторий.

## Какие будут вопросы и что отвечать

Сначала проверяются ядро и зависимости. Если нужна перезагрузка, установщик
остановится **до анкеты** и напечатает команду продолжения. Автоперезагрузки нет.

### 1. Какие VPN устанавливать

```text
Установить все совместимые VPN (оба AWG и один из VLESS/Hysteria 2)? y/n:
```

- `y` — оба AWG, затем выбор одного из VLESS/Hysteria.
- `n` — отдельный выбор AWG 2.0 и AWG 3.1 (`y`/`n`), затем:

```text
0 — Ничего не устанавливать (без VLESS и Hysteria 2)
1 — VLESS
2 — Hysteria 2
Выберите 0/1/2:
```

**Для установки только AWG 3.1:** `n` → AWG 2.0: `n` → AWG 3.1: `y` → `0`.
Установятся только выбранные компоненты. VLESS и Hysteria одновременно не ставятся.
Хотя бы один VPN должен быть выбран; бот без VPN этим установщиком не устанавливается.
Ответы на y/n-вопросы — латиницей `y` или `n`, а не `yes/no`.

### 2. Общие настройки

| Вопрос | Как отвечать |
| --- | --- |
| Публичный IPv4 сервера или auto `[auto]` | Enter — определить основной назначенный публичный адрес. При нескольких IP можно сразу указать нужный **исходящий IP VPN**. Он должен быть на интерфейсе. Если auto не может однозначно выбрать адрес, установка остановится с объяснением. |
| Домен VPN, или `-` без домена `[-]` | Например, `vpn.example.org` без `https://`, порта и пути. A-запись настраивается вручную. Enter/`-` — без общего домена; для Hysteria будет использован её обязательный TLS-домен, для VLESS mask — домен маскировки. |
| Имя первого VPN-пользователя `[vpnuser1]` | Например, `Pavel`: 1–32 символа, латиница, цифры, `.`, `_`, `-`. |
| Telegram ID администраторов через запятую | Свой числовой ID, например `123456789`; несколько — `123456789,987654321`. Это не username бота. |
| Токен Telegram-бота | Реальный токен BotFather. Символы при вводе не отображаются. Пустой или примерный токен не подходит. |
| Скорость канала, Мбит/с, или auto `[auto]` | Enter — Speedtest; либо число, например `100`. Это параметр канала, а не гарантированная скорость VPN. |

Для auto берётся округлённое вверх большее из download/upload. Если Speedtest
недоступен, заблокирован или вернул ошибку — предупреждение и **100 Мбит/с**;
установка продолжается. Выбранный IP и результат замера сохраняются и при обычном
продолжении повторно не определяются.

### 3. Порты и дополнительные вопросы

Вопросы появляются **только для выбранных VPN**:

| Компонент | Порт по умолчанию | Что учитывать |
| --- | --- | --- |
| AWG 2.0 | UDP 1234 | Можно оставить Enter, если порт свободен. |
| AWG 3.1 | UDP 1235 | Должен отличаться от других выбранных UDP-портов. |
| VLESS | TCP 443 | Далее обязательный выбор режима: `reality`, `direct` или `mask`. |
| Hysteria 2 | UDP 443 | Далее обязательный собственный домен и вопросы режима/сайта. |

У VLESS `reality` спрашиваются target (по умолчанию `www.google.com:443`) и SNI
(`www.google.com`). `mask` требует своего домена, правильной A-записи и TCP 80
для сертификата. `direct` не настраивает TLS-маскировку; выбирайте его осознанно.
Пустой ответ на обязательный вопрос режима не принимается.

Hysteria требует домен для TLS во всех режимах. Общий домен VPN, если задан,
должен совпадать с ним. Все A-записи должны вести на выбранный IP; эта IPv4-сборка
отклоняет AAAA домена Hysteria. Технические параметры режимов здесь не разбираются:
выбирайте явно по подсказкам установщика; при необходимости пароль можно
сгенерировать нажатием Enter. В режиме с сайтом спрашивается домен/HTTPS-адрес сайта.

Если сайт указывает на этот же сервер, но HTTPS ещё не настроен, установщик
попросит отдельное согласие `y/n` на локальный сертификат и страницу. На чужом
сервере сертификат не устанавливается. Для внешнего сайта нужен рабочий HTTPS;
при ошибке предлагается другой адрес. Получение и продление ACME требуют TCP 80.

## Что установщик проверяет и делает

1. Целостность пакета, root/Linux, поддерживаемую ОС, параметры и отсутствие чужой установки.
2. До анкеты — готовность ядра для AWG, headers и метапакет headers для следующих
   обновлений. При явном выборе только VLESS/Hysteria подготовка ядра AWG пропускается.
3. Нехватку RAM/swap, пакеты и зависимости; при необходимости останавливается для reboot.
4. Валидность каждого ответа до сохранения. Явные значения не заменяются auto.
5. Назначенный публичный IP и конфликты TCP/UDP, служебных портов и NAT-резерваций.
6. Резервные копии, затем последовательно только выбранные VPN, бот и worker.
7. AWG должен работать через модуль ядра: тихий Go fallback не считается успехом.
   Проверяются headers, DKMS и initramfs текущего, самого нового ядра и цели ссылки
   `vmlinuz`. Старые резервные ядра сами по себе не блокируют установку.
8. Настройку conntrack: ранняя загрузка модуля, лимит 65536, TCP TIME_WAIT 30 секунд.
   Заполнение более 80% не позволяет подтвердить успешную установку.
9. Локальную сетевую политику, выбранный исходящий IP, конфиги VLESS/Hysteria.
   Выход с выбранного адреса проверяется HTTPS-запросом; при неуспехе используется
   второй проверочный сервис. Это проверка source-bound выхода сервера.
10. Состав реестра, JSON выбранных CLI, ожидаемое состояние VPN-служб, бот, worker
    и таймеры статистики/канала.

Во время длительных операций выводятся действие, индикатор и путь журнала.
Без интерактивного терминала управляющие последовательности отключены. Ошибки,
вопросы и команда продолжения видны отдельно; подробный stdout/stderr хранится в логе.

Локальные проверки **не доказывают подключение телефона**, доступность из сети
оператора и фактический клиентский выход через NAT. Это проверяется после установки.

## Сеть, домен и несколько IP

Все назначенные публичные IPv4 на одном внешнем интерфейсе принимают VPN.
Один выбранный IPv4 используется для исходящего трафика VPN-пользователей.
Основной маршрут и служебный исходящий адрес самого сервера не переключаются.
IPv6 для VPN в этой сборке не используется; несколько WAN/шлюзов автоматически
не настраиваются. Внешние UDP-ответы AWG сохраняют адрес входа, SNAT применяется
к внутреннему клиентскому трафику.

Профили могут использовать домен: пользователь подключается к нему, а администратор
меняет A-запись вручную. В v4 нет приватных API регистратора/Netnum и встроенных
персональных ключей. Telegram API необходим самому боту; локальные API протоколов
также сохраняются. Пакеты, сертификаты, Speedtest и внешние IP-проверки используют Интернет.

В боте: **Администрирование → Настройки → Смена IP**.

1. Укажите **домен внешнего проверочного сервера**, а не URL или IP.
2. На проверочном сервере должны работать SSH/TCP 22 и HTTPS/TCP 443 с действительным
   сертификатом для домена. Firewall должен пропускать все проверяемые адреса.
3. Домен разрешается один раз. Со всех исходящих IP проверяется один показанный
   адрес назначения: SSH по banner без логина, HTTPS с проверкой сертификата/SNI и HTTP-ответа.
4. Бот показывает SSH/HTTPS отдельно: зелёный — оба доступны, жёлтый — один,
   красный — ни одного. HTTP 401/403 тоже подтверждает ответ HTTPS-сервиса.
5. Выбор IP и подтверждение меняют локальный выход VPN. Другие IP остаются входящими.
   Бот просит вручную изменить A-запись домена VPN. DNS самостоятельно не меняется.

Это доступность проверочного сервера **с VPN-сервера**, а не тест входящего VPN
из сети абонента. Приватные адреса назначения, URL, shell-вставки и параметры команд
не принимаются. Просмотр A-записи — только чтение DNS.

При смене IP домен в профилях сохраняется. Если профиль содержит числовой адрес,
может потребоваться повторная выдача профиля. Для Hysteria изменение выхода
допускается без смены TLS-домена; смена самого TLS-домена блокируется до отдельной
настройки сертификата. Автоматического мониторинга домена и переключения A-записей нет.

## Проверка после установки и первый клиент

1. Откройте своего бота в Telegram от указанного администратора и отправьте `/start`.
2. Откройте выбранный VPN, список пользователей и карточку первого клиента.
3. Получите ключ/QR для нужного приложения и ОС либо `.conf` для совместимого клиента.
   Установщик сам QR и ключи в консоль не печатает.
4. Импортируйте профиль, подключитесь из внешней сети, проверьте сайты и внешний IP.
   При нескольких входящих IP проверьте каждый отдельно: локальный тест не заменяет это.

Форматы ключей, `.conf`, QR для iPhone/Android и AmneziaVPN сохранены. Успешная
генерация QR не равна успешному подключению. Совместимость конкретного режима
и приложения проверяется на устройстве. Hysteria также выдаёт ссылку, QR и YAML для Clash.

Из каталога скачанного пакета:

```bash
bash check-server.sh
```

Дополнительная диагностика под root:

```bash
systemctl status vpnbot.service vpnbot-worker.service --no-pager
systemctl list-timers vpnbot-traffic.timer vpnbot-channel.timer --all
journalctl -u vpnbot.service -u vpnbot-worker.service -n 100 --no-pager
ip -br addr
ip route
```

`check-server.sh` проверяет выбранные протоколы, а не все возможные VPN. Их
ожидаемое состояние учитывается по настройкам бота. Журналы перед передачей
проверяйте на наличие секретов и пользовательских данных.

## Продолжение после reboot или ошибки

Ответы и этапы сохраняются в `/root/.vpnbot-global-v4.json` с правами 0600.
Каждый принятый ответ записывается сразу, атомарно. Завершённые этапы пропускаются.
Сохраните пакет и файл ответов до завершения установки.

Если установщик попросил reboot, перезагрузите сервер самостоятельно, затем
выполните **напечатанную команду продолжения** или `/root/install-v4.sh` той же версии.
Повтор до reboot не запускает подготовку ядра заново. Если после reboot загружено
неподходящее ядро, будет ошибка с просьбой проверить загрузчик/headers.

Прерванные пакетные операции и финальную проверку можно повторить. Для прерванного
этапа VPN/бота автоматический повтор блокируется: сначала сверьте журнал и реальное
состояние. Например, если проверено, что этап бота можно повторить:

```bash
/root/install-v4.sh --state-file /root/.vpnbot-global-v4.json --resolve-stage bot --stage-result retry &&
/root/install-v4.sh --state-file /root/.vpnbot-global-v4.json
```

Для действительно завершённого этапа используйте `--stage-result done` только после
сверки всех его действий. Команда `--resolve-stage` лишь фиксирует решение; сама
установку не продолжает. Имена: `backup`, `amnezia20`, `amnezia31`, `vless`,
`hysteria2`, `bot`. Не используйте `done`, чтобы спрятать ошибку.

Набор VPN/ответы после начала протокольных этапов менять нельзя. Не удаляйте JSON,
не правьте SQLite/контрольные точки вручную ради обхода проверки. `--state-file`
позволяет указать иной файл, но при продолжении нужен **тот же** файл состояния.

Журналы установки: `/var/log/vpnbot-global-v4/*.log`, каталог 0700, файлы 0600.
Временные журналы начальной загрузки сохраняются при ошибке, их путь показывается.
Известные секреты и строки с ключами/профилями фильтруются при записи.

## Точный набор VPN, проверка и тихая установка

Предварительная проверка скачивает пакет, затем проверяет его без установки
системных компонентов. Скачанный пакет/временные файлы загрузчика при этом создаются:

```bash
/root/install-v4.sh --check
/root/install-v4.sh --help
```

Для подробной справки основного установщика из пакета: `bash install-global.sh --help`.
Его `--check` проверяет пакет и входные настройки без системных изменений.
Фактически занятые порты исследуются при установке на целевом сервере.

Точный набор задаётся повторяемым `--onlyprotocol` **с первого запуска**:

```bash
/root/install-v4.sh --onlyprotocol amnezia31
# Или AWG 3.1 и VLESS:
/root/install-v4.sh --onlyprotocol amnezia31 --onlyprotocol vless
```

Допустимы `amnezia20`, `amnezia31`, `vless`, `hysteria2`.
Выбор через CLI заменяет вопросы о наборе VPN; остальные вопросы остаются.
VLESS и Hysteria одновременно запрещены. Установленные чужие конфликтующие
службы не удаляются и не останавливаются ради освобождения порта.

Из каталога пакета для INI:

```bash
cp silent.example.ini /root/install.local.ini
chmod 600 /root/install.local.ini
# Заполните файл своим редактором, затем:
bash install-global.sh --check --silent --config /root/install.local.ini
bash install-global.sh --silent --config /root/install.local.ini
```

`--config` без `--silent` разрешает вопросы по недостающим ответам. `--silent`
запрещает их: неполные обязательные настройки/конфликты останавливают установку.
Приоритет: CLI → окружение → INI → сохранённые ответы. После начала установки
протоколов сохранённый план защищён от изменения. Несогласованные наборы в INI
и `--onlyprotocol` вызывают ошибку, а не молчаливую замену.

В секции `[protocols]` шаблона INI сейчас поддерживаются `yes/no` для AWG и
`vless_or_hysteria2 = 1/2`. Пункт `0` работает в интерактивном меню, **не в INI**.
Для тихой установки только AWG удалите **всю секцию `[protocols]`** и задайте
`--onlyprotocol amnezia31` вместе с `--silent --config /root/install.local.ini`.
Неиспользуемые секции настроек протоколов сами по себе ничего не устанавливают.
INI с токеном должен принадлежать запускающему пользователю и иметь права 0600;
в поставку включён только шаблон без действующих секретов.

## Порты

TCP и UDP проверяются отдельно, включая IPv4/IPv6 слушатели, nftables/NAT и legacy
iptables NAT при наличии. TCP 443 и UDP 443 совместимы. Два выбранных UDP-сервиса
на одном порту — конфликт. Чужие слушатели автоматически не выключаются.

| Назначение | Порт |
| --- | --- |
| AWG 2.0 / AWG 3.1 | Выбранные UDP, по умолчанию 1234 / 1235 |
| VLESS | Выбранный TCP, по умолчанию 443 |
| Hysteria 2 | Выбранный UDP, по умолчанию 443 |
| ACME для VLESS mask / Hysteria | TCP 80, нужен извне |
| VLESS API | TCP 10085, служебный |
| VLESS mask backend | TCP 12710, служебный |
| Hysteria API | TCP 19090, служебный |
| Локальная HTTPS-страница Hysteria | TCP 443 или порт в адресе сайта |

Служебные API предназначены для локального доступа; не открывайте их наружу.
Порты 22 и 443 внешнего проверочного сервера нужны только для функции проверки IP,
они не означают обязательную установку SSH/HTTPS-сайта на каждом VPN-сервере.

## Бот, очередь и временные ошибки Telegram

Бот и `vpnbot-worker.service` работают отдельно. Меню не ждёт длинных серверных
изменений. Серверные операции выполняются последовательно, результаты сохраняются
в SQLite и отправляются отдельно. Права проверяются перед выполнением и выдачей.
Повтор одного Telegram update не создаёт вторую задачу; отдельные нажатия — отдельные запросы.

Временные DNS/reset/timeout/429/5xx ошибки отправки в Telegram обрабатываются
повторными запросами с ограничением числа попыток; технический текст не выводится
клиенту. Ошибка отправки результата не должна заново выполнять VPN-изменение.
При неопределённом результате отправки возможен дубликат сообщения.

Прерванные чтения возвращаются в очередь. Неопределённые изменения получают
`needs_review` и блокируют дальнейшие задачи до сверки состояния. После неё:

```bash
cd /root/vpnbot
python3 worker.py --resolve 42 --result done
# либо --result failed; 42 замените реальным номером задачи.
```

Не меняйте очередь вручную и не подтверждайте непроверенную операцию.

## Что нового относительно v3

- Фиксированный исходящий IPv4 VPN при приёме на всех публичных IPv4; служебный
  маршрут сервера сохраняется отдельно. Настройки сверены с рабочей схемой USA.
- Домен VPN задаётся вручную; никаких персональных DNS API. После смены IP —
  явное напоминание человеку изменить A-запись.
- Проверочный домен запрашивается в боте; SSH и HTTPS проверяются отдельно
  с каждого адреса, с валидацией домена и фиксацией одного IP назначения.
- Проверки ядра/headers/DKMS/initramfs, отсутствие тихого Go fallback и headers-метапакет.
  Проверка старых резервных ядер не блокирует установку без необходимости.
- Подготовка swap на малой RAM и контроль заполнения conntrack.
- Повторы временных ошибок Telegram без выдачи клиенту технического traceback.
- Выбор `0` позволяет интерактивно установить только AWG без VLESS/Hysteria.
- Исправлена загрузка проверки ядра по реальному установленному имени файла.
- Отдельный корневой загрузчик `install-v4.sh`; v2, v3 и Personal не заменяются.

От v3 сохранены выбор протоколов, анкета и сохранение ответов, INI/тихий режим,
проверки портов, пропуск завершённых этапов, контролируемое продолжение,
очередь, профили/QR, статистика и резервные копии.

## Файлы, тесты и откат

- Исходники: `bots/vpn-manager_awg/v4/` в репозитории.
- Вход установки: `install-global.sh` внутри пакета; локальный `install-v4.sh`
  внутри пакета только вызывает его. **Корневой** `install-v4.sh` скачивает пакет.
- Рабочий бот: `/root/vpnbot`; контроллеры: `/usr/local/sbin/awgctl`, `awg3ctl`,
  `vlessctl`, `hysteria2ctl` — только для выбранных протоколов.
- Настройки Hysteria: `/etc/hysteria`; CLI не перезапускает VPN при добавлении
  пользователя, при удалении отключает соответствующего клиента.
- Состояние/домены сетевой политики: `/etc/vpnbot-global/`.
- Резервные копии: `/root/vpnbot-backups/`.

Тесты из каталога `bots/vpn-manager_awg` **внутри пакета v4**:

```bash
python3 -m unittest discover -s tests -q
```

Они проверяют обработчики/права, очередь/сбои, продолжение, порты, INI/auto,
сетевые транзакции и сохранность форматов. Сборщик исключает приватные интеграции
и встроенные токены. PNG-тест требует qrencode/Pillow и может быть пропущен локально.
Реальный выпуск сертификата и подключение устройства тестируются на сервере.
Обнаруженные при пробной установке на bg2 ошибки проверки старых headers и импорта
исправлены. Подтверждения полностью завершённой установки/подключения от этой
пробы пока нет. Проверки GitHub Actions для v3 не являются проверками v4.

Откат требует согласованного восстановления конфигураций VPN, CLI, бота и баз
из одной резервной копии; копирование одной старой SQLite поверх работающего
сервера не является откатом. Не запускайте v2/v3 поверх v4 как способ отката.
Форматы и ограничения генерации описаны в [PROFILE_FORMAT_CONTRACT_RU.md](PROFILE_FORMAT_CONTRACT_RU.md).
Дополнительные результаты проверок: [VALIDATION_RU.txt](VALIDATION_RU.txt).
