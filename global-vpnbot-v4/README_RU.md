# Global VPN Bot v4

Отдельная сборка `global-v4-2026.11.15.1` для нового сервера Debian 13 / Ubuntu 24+.
Основа — Global v3; поведение ядра, сети, conntrack и повторов Telegram сверено
с рабочим USA 15.11.2026. Global v2/v3, Personal и работающие серверы не изменяются.
Установка поверх ранее настроенного бота/VPN запрещена. Это не обновление Personal.

## Запуск из полного архива

```bash
tar -xzf vpnbot-global-v4-2026.11.15.1.tar.gz
cd global-vpnbot-v4
bash install-global.sh --check
sudo bash install-global.sh
```

Для набора как на USA — только AmneziaWG 3.1:

```bash
sudo bash install-global.sh --onlyprotocol amnezia31
```

Вариант `bash install-v4.sh` вызывает этот же локальный установщик. Отдельный файл
не скачивает старые версии. Сборка пока не опубликована в GitHub; используйте архив.

## Что устанавливается

- AmneziaWG 2.0 / AmneziaWG 3.1 по выбору; VLESS или Hysteria 2 взаимоисключающие.
- Telegram-бот с административным и пользовательским меню, правами доступа,
  приглашениями, профилями, QR, статистикой и отдельной очередью серверных операций.
- Для AWG 3.1 включены RandomTrailers и DisableCookies, как на USA. S/H и ключи
  генерируются для нового сервера: ключи USA и пользовательские профили не копируются.
- Форматы `.conf`, iPhone/Android QR, native AmneziaVPN QR и `vpn://` сохранены.
- Повторы временных ошибок Telegram/DNS/connection reset. Ошибки транспорта не
  выводятся пользователю техническим текстом. Неопределённые изменения VPN не
  повторяются автоматически. Потерянный ответ Telegram может дать дубликат сообщения.

## Сеть

На одном внешнем интерфейсе все назначенные публичные IPv4 принимают VPN.
Администратор выбирает один исходящий IPv4 VPN-пользователей. Служебный default
route/source самого сервера не меняется. IPv6 в этой сборке не используется для VPN.
VLESS и Hysteria слушают все IPv4, их исходящий адрес настроен отдельно.
Внешние UDP-ответы AWG сохраняют адрес входа; SNAT применяется к клиентскому трафику.

При смене исходящего IP ключи и обфускация сохраняются. Если в профилях используется
домен, он сохраняется; если IP — нужны обновлённые профили. Бот напоминает:
**«Просьба вручную изменить A-запись домена VPN на выбранный IP»**.
Все остальные IP продолжают принимать VPN, обновление A-записи выполняет человек.
Несколько WAN/шлюзов не настраиваются автоматически.

## Домены и отсутствие персональных API

В сборке нет Domeny/Netnum API, приватных модулей регистратора, токенов управления
инфраструктурой и персональных ключей. Никто не получает доступ к аккаунту DNS.
Домен VPN администратор вводит сам. A-записи создаёт и меняет вручную у своего DNS-
провайдера. Проверка A-записей через `host` только справочная, без DNS-записей.

Telegram Bot API необходим самому боту: токен вводится при установке и записывается
локально с правами 0600. В архиве только пример настроек без действующих секретов.
CLI протоколов используют свои локальные loopback API. Загрузка пакетов, ACME,
Speedtest и открытые сервисы проверки внешнего IP требуют доступа в Интернет;
они не используют персональные аккаунты/API-ключи владельца этой разработки.

Для Hysteria/HTTPS-маскировки A-запись TLS-домена должна быть настроена заранее,
TCP 80 доступен для ACME. Для этой IPv4-сборки не должно быть ошибочной AAAA.
Изменить исходящий IP Hysteria можно без смены TLS-домена; смена самого TLS-домена
блокируется до отдельного обновления сертификата/переустановки протокола.

## Проверка IP из бота

1. Администрирование → Настройки → Смена IP.
2. Бот просит **домен внешнего проверочного сервера**.
3. На этом сервере должны быть SSH на TCP 22 и HTTPS на TCP 443 с действительным
   сертификатом для домена. Его firewall должен пропускать все проверяемые IP.
4. Проверка выполняется с каждого назначенного IP VPN-сервера. Домен разрешается
   один раз; для всех запросов используется один показанный адрес назначения.
5. Для каждого IP показываются отдельно SSH и HTTPS: зелёный — оба, жёлтый — один,
   красный — ни одного. Это доступность проверочного сервера, а не доказательство
   доступности VPN из сети конкретного абонента.
6. После выбора и подтверждения меняется локальный выход VPN. DNS не меняется.

SSH проверяется по banner без логина/пароля. HTTPS проверяет TLS, SNI и HTTP-ответ;
ответ 401/403 тоже подтверждает доступность сервиса. Указанный домен — не домен VPN.
URL, IP-адрес, опции команд, wildcard, пробелы и shell-вставки запрещены. Запросы
выполняются argv/socket без shell; приватные/локальные адреса назначения запрещены.

## Проверки во время установки

1. Целостность пакета, ОС, root, отсутствие чужой установки и безопасность ответов.
2. До анкеты: версия ядра, headers текущего ядра и метапакет headers для следующих
   обновлений. На малой RAM при нехватке swap добавляется 1 ГиБ с проверкой диска.
3. Если сначала надо загрузить новое ядро — остановка с кодом 75 и точной командой
   продолжения. Автоматической перезагрузки нет; ответы сохраняются.
4. Явный выбор протоколов, исходящего IP/auto, домена или `-`, администратора, токена,
   первого клиента, портов и скорости/auto. При недоступном Speedtest сохраняется 100 Мбит/с.
5. Конфликты TCP/UDP/служебных портов и привязка публичного IP к интерфейсу.
6. Резервные копии и установка только выбранных модулей.
7. AWG должен использовать модуль ядра. При старте служба проверяет его: тихий Go
   fallback не считается успехом. Проверяются DKMS, headers и initramfs загрузочных ядер.
8. Conntrack: ранняя загрузка `nf_conntrack`, лимит 65536, TCP TIME_WAIT 30 секунд.
   Заполнение более 80% останавливает подтверждение установки.
9. Все входящие IPv4, выбранный выход, локальные конфиги VLESS/Hysteria, реальный
   HTTPS-выход с выбранного адреса через два независимых проверочных сервиса.
10. JSON выбранных CLI, ожидаемое состояние VPN-служб, бот, worker и таймеры.

После установки:

```bash
sudo bash check-server.sh
```

Проверка не сканирует выключенные/невыбранные протоколы. Она не заменяет внешний
тест подключения с телефона: для него нужен клиент в другой сети. Установщик не
может доказать прохождение VPN через сеть конкретного оператора одним локальным тестом.

## Продолжение, пропуск этапов и остановки

Ответы и контрольные точки: `/root/.vpnbot-global-v4.json`, 0600. Каждый принятый
ответ сразу записывается атомарно. Завершённые этапы пропускаются при продолжении,
пакеты устанавливаются идемпотентно. Настроенные чужие VPN не переписываются.
Если неизвестно, завершилась ли серверная операция, автоматический повтор блокируется:

```bash
sudo bash install-global.sh --resolve-stage amnezia31 --stage-result done
# либо retry, только после проверки реального состояния сервера.
```

Затем повторите команду продолжения. `--state-file` позволяет выбрать другой файл.
Ошибки проверки и пакетов можно повторить безопасно; изменение набора VPN после
начала установки протоколов запрещено. `--onlyprotocol` повторяется для точного набора.

Для тихой установки заполните `silent.example.ini`, сохраните как `install.local.ini`
с правами 0600 и запустите `--silent --config /путь/install.local.ini`.
В релиз включён только шаблон. Не публикуйте файл с токеном.

## Проверка этой сборки

Исполняются тесты установщика, продолжения, меню/авторизации, очереди/повторов,
транзакций сети/отката, безопасного SSH/HTTPS probe и сохранности генераторов.
Сборщик проверяет отсутствие приватных интеграций и встроенных токенов.
Полная первая установка на чистый сервер пока не выполнена; на USA проведено
только чтение эталонной конфигурации. Существующие серверы и версии не обновлялись.
Тест генерации PNG требует qrencode/Pillow; на локальном macOS он может быть пропущен.
Смотрите также `PROFILE_FORMAT_CONTRACT_RU.md` и `VALIDATION_RU.txt` в корне пакета.
